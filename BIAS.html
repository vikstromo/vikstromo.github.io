BIAS — Process & Documentation

Basically BIAS is supposed to be a companion to me when playing woodwinds. I'm a musician that works with improvisation as my main method for making music. Everything is done in SuperCollider, except for adding some minor post-production on the clarinet sound in a DAW.
I am very inspired by early Swedish electronic music. I'm terrible at doing music using sequencers. I like impulses(emotional, not electric). I like white noise, filters and sine waves and what you can do with some simple cooking.

BIAS can be divided into four steps.

It receives sound from an audio input. It then has what I call a slow listener. It gives an output that answers "How have I've been playing recently?". this is tricky and not perfect at all. But it gives me a value(0-1) that answers how active I've been lately. So if I have played a lot, then it gives me 1, if I have been mostly silent -> 0. This can function as an LFO for other parameters during performance. Then there is a simple sample recorder and a sample playback. I use an IntraMic from Viga Tools to get a signal with almost zero noise and no feedback.

Both audio and data goes into the heart of the system. Here I use my modules/synths. Instead of having synths that I control using midi or controlling by a graphic interface, I feed data to the synths. Amplitude, pitch-info, spectral centroid and flatness are used to trigger sound, changing sound, changing pitch, triggering calculations for various stuff. Most of the modules also has a slight generative, or independent, behaviour built in. This is so that the modules do not depend on me to play themselves. All of these modules sum up to a shared signal that then goes in to the fx chain. I'm not an expert on synthesis or synth design. So the library is growing and changing a lot.

Im not interested in creating a loop station for my clarinet. So the clean clarinet signal is not going past the modules. If I sample something, it is mostly the processed signal. And then I can feed that sample in to the modules again. This can create some really fun layers.

The synths go into an FX chain. The fx-chain system allows me to click-free(almost) swap the order of effects. This opens up for some fun experiments. It started out with the idea to have like a pitch shifting reverb. Usually when I design effects for my music in SuperCollider I try to achieve these big effects that have a lot of different functions. Someone at sccode.org posted this sitar-synth which split the instrument into the attack(finger/pick), the string, the resonator and the room. I started messing around with this and realized this was way smarter than building a one-piece synth. So what I did was to divide my pitch shifting reverb into three parts. The delay, the pitch and the time. Later, I added a blur as well. Then I started experimenting with shifting the order of these things and got some very fun sound. I then added a binshift, a formant and some echo and feedback delays. Then I added some functionality so that I could swap the order really quick and easy. And I centralized the whole system so that I use 4 macros to control all of the effects. Chaos, density, space and identity.

The last part is just a synth that can do some spatialisation. Autopanning, and expand the system to a multichannel setup. Every chain has it's own spatial synth. This makes it possible to create some fun movements in a live setup.

I control the system using a Morningstar MC6 foot pedal and a Faderfox UC4 midi controller. Mostly I just set a "mood". This is like a preset. It includes which modules to choose, some base values for the parameter, the fx-chain and some presets there to. The idea is to have some kind of control of the system. There is no price for me if I have a completly indepedent system. Just as long as it is fun to play with and sounds good. The fun comes from getting a lot of inspiration when playing. So with my physical controllers I can sample either the clean recording or the sound from the modules. I can choose a mood. I can choose if the mood is going to follow my playing or counter it. I can also make some mixing if necessary and I can change the parameters if it sounds bad or not fun enough. I can also use an expression pedal to morph between different parameter values for the modules.

The Code

A snippet of the behavioral agent logic in SuperCollider:

(
// Behavioral Agent: Frequency Analysis to Memory
SynthDef(\biasAgent, { |in=0, threshold=0.1|
    var input = AudioIn.ar(in);
    var freq, hasFreq;
    # freq, hasFreq = Pitch.kr(input);
    
    // Logic for behavior shifting based on recent pitch history
    SendReply.kr(Impulse.kr(10), '/pitchData', [freq, hasFreq]);
}).add;
)
