Once I decided to get started with this site as a way to keep an open documentation, most of the work was already done. I will however try to keep this "blog" active as I change things, and then I can try to make some explanations on the way. 

Most of the code is strucutred around simple dictionaries. After trying some different ways the last 2 years I find this to be the best way to keep the code safe.

Since I did this project with the idea of having 8 channels I make 8 copies of each storage dictionary. Then I have one dictionary for functions as well. 


```
~fbs = Array.fill(8, {|i|
    (
        state: \idle,
		sourceStates:  (
    audioIn: [\play, \chop],
    play:    [\audioIn, \chop],
    chop:    [\audioIn, \play]
),

        group: nil,
		buses: ~bus[i] // This can then be reached with ~fbs[i].buses.key
		firstGroup: nil,

		groupArgs: [],
		rawBus: ~bus[i].raw, // use this syntax for the busses for some reason. Easier to read and write.
		recMode: nil,

        source: (
            type: nil,      // \audioIn or \play
            synth: nil,
			role: nil,  // \live | \resample. is used for setting index 0 to \live, which cant be resampled(That can only be muted or unmuted)
			out: nil;
        ),

       



    ) // close ~fbs
});
```

Then I have some functions in another dictionary. And I find this syntax to be very clean and easy to work with. 

First I create an empty dictionary. 

```~fb = (); ````

Then when I create new functions I add a new key to them. This is a way to minimize the number of global variables that I normally use. As you can see in my ~fx-chain code in the Code-section. When I have time I will rewrite that as well. 

````
~fb.createSynth = {|self, i, type|
var v = ~fbs[i]; // This is to acess the storage dictionary
var synth; 


if(  v[\state] == \playing ) {^nil};
synth = Synth(type, [], v[\group]);

v[\source][\synth] = synth;

v[\source][\state] = \playing

}
```

So this is a basic example. But what I get from this is a security that I cant run another synth on that index. And it is also possible to store params to make morph functions between different presets and stuff. 

And then you can make one function that calls other functions. Lets add "create group" and then a "launch synth". 

```
~fb.createGroup = {|self, i|
var v = ~fbs[i];
if (v[\group].isNil)
{group = Group.new; };
{^nil};

v[\group] = group;


};

~fb.launch = {|self, i|
var v = ~fbs[i];

self.createGroup(i)
self.createSynth(i);



};

```

This is still very basic. But once I learned to write my system this way I could easily scale it, rebuild it, add new functionality. It's very easy to add debugging messages in the ~fb.launch to see what function is not working. And it is fun to write a clean system as well. 

When we start storing values we can also easier do stuff like kill an index, then start from where we left of. Even if we spread our stuff all over the node tree we can access them easily through simple functions. 

This is probably all very simple. I know that Eli Fieldsteel use this in his book for events, which I used. But I think this structure is even more clean than his examples in the book.
